# Platform Features

DentalIQ is a multi-tenant SaaS platform for Canadian dental clinics. Features are gated by plan tier. Below is a complete breakdown of what each plan includes, how the demo engine works, and the key platform subsystems.

---

## 1. Plan Tiers

### Starter — $199/mo

The entry-level plan focuses on core operational tools with no AI dependency.

- **Dashboard Overview** — Key metrics: total patients, monthly revenue, claim stats, recent activity feed
- **Patient Management** — Patient directory with demographics, insurance info, visit history, and notes
- **Insurance Estimator** — CDT-code-based fee estimation using rules engine (instant, no LLM required)
- **Claims Tracking** — Track estimate submissions, risk flags, and claim outcomes
- **Basic Analytics** — Monthly revenue trends, top procedures, patient volume charts
- **Support Portal** — In-app ticketing and live chat with the DentalIQ support team

### Pro — $349/mo

Adds AI capabilities and multi-location management on top of the Starter tier.

Everything in Starter, plus:

- **AI Explanations** — Plain-language summaries of coverage decisions generated by the LLM
- **Pre-Auth Narrative Generation** — AI drafts clinical justification letters for complex CDT codes in ~90 seconds
- **Claim Risk Detection** — ML-based flags for submissions likely to be denied before sending
- **AI Copilot (Chat)** — Context-aware assistant in the dashboard that understands current clinic state (patients, claims, staff notes) and answers operational questions
- **Multi-Location Support** — Manage multiple clinic locations under one tenant account with a location switcher

### Cortex — $299/mo + $1.50/approved action

Activates the autonomous AI workforce. Priced separately from Pro because it can be added independently.

Everything in Pro, plus:

- **6 Autonomous AI Agents** — Billing, Recall, Review, Supply, Treatment Coordinator, Hygienist (see §4)
- **Cortex Command Center** — Real-time dark-mode terminal UI showing live agent activity logs
- **Approval Inbox** — Agents queue tasks for human review; nothing executes without explicit approval (human-in-the-loop design)
- **Per-action billing** — Only charged for tasks you approve, not for tasks generated or rejected

### Enterprise — Custom Pricing

For large DSOs (Dental Service Organizations) and multi-province networks.

Everything in Cortex, plus:

- **Custom Contract & SLA** — Dedicated support, uptime guarantees, custom onboarding
- **SSO / SAML Integration** — Connect existing identity providers (Azure AD, Okta, Google Workspace)
- **Custom AI Models** — Fine-tuned models trained on your clinic's historical approval patterns
- **Advanced Analytics** — Cross-clinic benchmarking, revenue cycle analytics, CDCP compliance reports
- **Data Residency Guarantees** — Canadian data centre contractual commitments
- **API Access** — Full REST API access for PMS integration and custom workflows

## 3. The Demo Engine (`/demo/[plan]`)

The demo routes let anyone explore the full dashboard experience without creating an account or touching the database. Useful for sales demos, marketing, and developer testing.

### How It Works

- **Fully static** — All data is hardcoded `useState` variables. No API calls, no auth token required.
- **1-to-1 UI replication** — The demo pages use the same layout, components, and visual design as the authenticated dashboard.
- **Plan-locked features** — Demoing `starter` visually dims/disables Pro and Cortex features, showing the upgrade value proposition in context.
- **Simulated live activity** — `setInterval` loops simulate agent activity, notification pings, and metric updates.

### Enabling Demo Routes

```bash
# In .env:
NEXT_PUBLIC_ENABLE_DEMO=true
```

| URL                                | Shows                                  |
| ---------------------------------- | -------------------------------------- |
| `http://localhost:3000/demo/starter` | Basic estimator, no AI features      |
| `http://localhost:3000/demo/pro`     | Estimator + AI Copilot chat          |
| `http://localhost:3000/demo/cortex`  | Full agent command center + inbox    |

> **Important:** Always leave `NEXT_PUBLIC_ENABLE_DEMO` unset in production deployments serving real clinics. Demo routes expose simulated but realistic-looking clinical data.

## 4. Cortex Agents

Each Cortex agent is a specialized autonomous worker. Agents run on a nightly schedule (2:00 AM) and generate tasks that humans review before any action is taken.

### Agent Roster

| Agent                  | Code      | Accent Color | What It Does                                                              |
| ---------------------- | --------- | ------------ | ------------------------------------------------------------------------- |
| **Billing Agent**      | CORTEX-01 | Purple       | Scans unpaid invoices, drafts pre-auth narratives, prevents CDCP denials  |
| **Recall Agent**       | CORTEX-02 | Sky Blue     | Identifies overdue hygiene patients, drafts recall messages               |
| **Review Agent**       | CORTEX-03 | Amber        | Finds satisfied post-visit patients, drafts review request messages       |
| **Supply Agent**       | CORTEX-04 | Emerald      | Compares inventory levels against upcoming procedure bookings             |
| **Treatment Coord.**   | CORTEX-05 | Pink         | Follows up on high-value treatment plans that weren't scheduled           |
| **Hygienist Agent**    | CORTEX-06 | Teal         | Matches last-minute cancellation slots against the waitlist               |

### Human-in-the-Loop Design

Agents **never** take external actions autonomously. The full flow:

```
Agent detects actionable item
  → Generates proposed action via LLM
  → Creates task: status = "pending"
  → Task appears in clinic's Approval Inbox
  → Clinic staff reviews: Approve or Reject
  → If Approved: action executes (email sent, letter exported, etc.)
  → If Rejected: task closed, no action taken
```

This design ensures staff remain in control and AI errors don't affect patients.

## 5. Stripe Billing Integration

DentalIQ uses Stripe for subscription management. Stripe is fully optional — if not configured, billing pages show "Payment not configured."

### Implementation Details

- **SetupIntents + Subscriptions** — Cards are tokenized client-side via Stripe.js (PCI DSS compliant)
- **Webhook handling** — `tenant-service` processes Stripe events: `invoice.paid`, `customer.subscription.updated`, `customer.subscription.deleted`
- **Plan upgrades** — Subscription updates are applied immediately via proration
- **Cortex per-action billing** — Each approved agent task is metered and invoiced monthly

### Test Mode

In development, use Stripe test mode. Test cards:

| Card Number           | Scenario                  |
| --------------------- | ------------------------- |
| `4242 4242 4242 4242` | Always succeeds           |
| `4000 0000 0000 9995` | Always declined           |
| `4000 0025 0000 3155` | Requires 3D Secure        |

## 6. Support & Ticketing

The support system combines live chat with persistent ticketing.

### Live Chat (Support Bot)

- Context-aware AI assistant that can look up account details, answer plan questions, and triage issues
- Backed by the same `llm-interface` package used by the rest of the platform
- Falls back to "request will be reviewed by a human" when LLM is unavailable

### Ticketing

- Create, track, and resolve support tickets
- Categories: bug, billing, integration, feature request, other
- Status indicators: open, in-progress, resolved
- Full message thread history per ticket

## 7. Insurance Estimator

The core feature available on all plans. Generates instant cost breakdowns from CDT procedure codes.

### How It Works

1. Staff enters one or more CDT codes (e.g., D2750 — Crown)
2. Rules engine looks up the fee schedule and standard coverage percentages (<1ms)
3. **Pro/Cortex**: LLM generates a plain-language explanation of the coverage decision
4. **Pro/Cortex**: Option to generate a full pre-authorization letter narrative
5. Result: itemized cost breakdown showing patient portion, insurer portion, and risk flags

### Pre-Auth Narrative Generation

When enabled (Pro+), clicking "Generate Letter" on an estimate:

1. Sends procedure details, patient info, and insurer to the estimate service
2. Estimate service builds a specialized prompt and calls the configured LLM
3. LLM generates a formal clinical justification narrative (~90 seconds with Ollama 8b)
4. The generated text is returned in an editable textarea for dentist review
5. Dentist can modify before exporting to PDF or copying into their PMS
